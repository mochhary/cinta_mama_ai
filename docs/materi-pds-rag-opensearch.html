1.0 Ringkasan Eksekutif dan Transformasi Sistem

Dalam implementasi sistem tanya-jawab cerdas berbasis Large Language Model (LLM), keterbatasan utama model murni adalah ketidaktahuannya terhadap data internal yang bersifat privat, spesifik organisasi, atau berada di luar batas waktu pelatihan (knowledge cutoff).

Sistem CintaMamaAI telah berhasil dimodernisasi dari chatbot berbasis inferensi mandiri menjadi arsitektur Retrieval-Augmented Generation (RAG) terintegrasi penuh. Sistem tidak lagi membiarkan LLM menebak fakta operasional secara spekulatif, melainkan memasok konteks faktual dari knowledge base resmi sebelum kalimat jawaban dirangkai.

Aspek Evaluasi Sebelum Implementasi RAG Sesudah Implementasi RAG
Sumber Pengetahuan 100% parameter bobot internal model Llama 3.2 (pengetahuan global pra-pelatihan). Kombinasi parameter bahasa model dan basis data vektor resmi OpenSearch.
Risiko Halusinasi Tinggi ketika dihadapkan pada pertanyaan SOP internal, Git workflow, atau konfigurasi lokal. Rendah karena instruksi sistem mewajibkan pemanfaatan fakta rujukan yang dilampirkan.
Mekanisme Respons Jawaban bersifat generik, spekulatif, atau menolak karena keterbatasan informasi model. Jawaban presisi, mengutip nama branch resmi, command script, dan tahapan SOP.
Fleksibilitas Pembaruan Membutuhkan fine-tuning atau re-training berkala yang mahal dan lambat. Sangat cepat; cukup mengindeks dokumen markdown baru ke index OpenSearch.

2.0 Glosarium Konseptual dan Komponen Arsitektur

Fondasi Teori: Tiga Pilar Utama RAG
RAG beroperasi atas sinergi tiga pilar: Retrieval (pengambilan data relevan berbasis kedekatan matematis), Augmentation (pengayaan instruksi sistem dengan menyuntikkan dokumen), dan Generation (sintesis jawaban terstruktur oleh model bahasa).

2.1 Definisi Komponen Teknis

  • Vector Embedding: Representasi matematis teks dalam ruang multidimensi. Menggunakan model nomic-embed-text, setiap teks diproyeksikan menjadi vektor berukuran 768 dimensi berupa bilangan riil terstandardisasi (unit vector dengan norma Euclidean bernilai 1.0).
  • Vector Database (OpenSearch 2.11.0): Mesin pencari terdistribusi dengan plugin k-NN (k-Nearest Neighbors) aktif. Berperan menyimpan vektor dokumen dan menyediakan eksekusi pencarian vektor berkecepatan tinggi menggunakan algoritma graf hierarkis NMSLIB/HNSW.
  • Cosine Similarity: Metrik pengukuran derajat kesamaan orientasi antara dua vektor. Dirumuskan sebagai:
    Sim(A, B) = (A · B) / (||A|| × ||B||)
    Karena vektor embedding telah ternormalisasi (||A|| = ||B|| = 1), nilai Cosine Similarity setara dengan hasil kali titik (*dot product*) dari kedua vektor tersebut.
  • Prompt Injection / Context Window Management: Teknik penataan instruksi di mana dokumen rujukan hasil retrieval disisipkan di dalam system prompt sebelum pertanyaan pengguna diproses oleh LLM.
  • NDJSON Real-time Streaming: Pengiriman data terstruktur berbasis Newline Delimited JSON melalui protokol HTTP Chunked Streaming, memungkinkan latensi awal (Time-to-First-Token) yang sangat singkat bagi pengguna.

3.0 Diagram Alur Sistem dan Siklus Eksekusi (Lifecycle)

Setiap permintaan yang masuk melalui endpoint POST /chat/stream atau POST /generate/stream diproses melalui pipa aliran data (data pipeline) bertahap sebagai berikut:

1
Validasi Request dan Guardrail Keamanan
FastAPI memvalidasi payload request. Jika daftar messages kosong atau elemen terakhir bukan berstatus role: user, sistem langsung memutus koneksi dan mengembalikan HTTP 400 Bad Request, mencegah komputasi sia-sia.
2
Ekstraksi Pertanyaan dan Transformasi Vektor (Embedder)
Teks pertanyaan pengguna terakhir diekstraksi dan dikirimkan secara internal via HTTP POST ke endpoint http://ollama:11434/api/embeddings. Model nomic-embed-text menghasilkan vektor 768 dimensi dalam waktu ~15-25 ms.
3
Pencarian Semantik k-NN di OpenSearch
Vektor query dikirim ke OpenSearch index cinta-mama-docs. OpenSearch menghitung jarak kosinus terhadap 16 dokumen SOP pemrograman dan mengembalikan daftar hits terurut beserta skor kemiripannya.
4
Konstruksi Konteks Dokumen (Augmentation)
Sistem mengambil RAG_TOP_K = 3 dokumen teratas. Masing-masing dokumen dipotong maksimal 1.200 karakter (snippet truncation) guna menjaga ukuran prompt tetap efisien dan menghindari beban evaluasi token berlebih pada CPU Docker.
5
Penyusunan System Prompt Terarah
Persona hangat CintaMamaAI digabungkan dengan cuplikan dokumen SOP resmi menggunakan instruksi eksplisit: "Utamakan penggunaan fakta teknis, konfigurasi, dan langkah operasional dari konteks di atas."
6
Inferensi Autoregresif oleh Llama 3.2
Kombinasi System Prompt dan riwayat percakapan dikirim ke endpoint http://ollama:11434/api/chat. Model Llama 3.2 (3B) mengevaluasi konteks secara bertahap dan men-decode token output satu demi satu.
7
Pengaliran Token Real-Time ke Klien
FastAPI mem-forward baris demi baris token dari Ollama ke browser atau Postman secara asinkron menggunakan StreamingResponse(media_type="application/x-ndjson") hingga token penutup done: true terkirim.

5.0 Analisis Masalah Ruang Vektor dan Strategi Mitigasi

5.1 Fenomena "Score Crowding" pada Dokumen Terstruktur Serupa

Pada saat menguji kueri dengan 16 dokumen SOP pemrograman, teramati bahwa seluruh dokumen memiliki skor kemiripan yang terkumpul rapat di rentang 0.7000 - 0.7300, meskipun bahasa pemrogramannya berbeda jauh (misal: Java, Swift, Kotlin).

Penyebab Matematis
Dokumen SOP memiliki struktur tata bahasa dan format markdown yang seragam (bagian Tujuan, Prasyarat, Perintah CLI, dan Verifikasi). Vektor embedding menangkap kesamaan sintaksis struktural ini sebagai kemiripan geometris pada ruang kosinus.

5.2 Strategi Optimasi yang Diterapkan

  1. Penetapan RAG_TOP_K = 3: Membatasi hanya 3 dokumen teratas yang dilampirkan, sehingga model tidak kebingungan membedakan konteks yang mirip.
  2. Pemotongan Snippet (1.200 Karakter): Mencegah prompt token meledak melebihi batas 2.000 token pada CPU Docker yang dapat memperlambat inferensi hingga 4 kali lipat.
  3. Persistensi Fallback: Jika layanan OpenSearch tidak merespons, blok try-except di [app/main.py] mengembalikan string kosong sehingga chatbot tetap berfungsi melayani percakapan umum tanpa memunculkan HTTP 500 error.

6.0 Implementasi Kode Inti

Berikut adalah cuplikan fungsi inti retriever yang diintegrasikan ke dalam backend FastAPI: 

# app/main.py - Fungsi Retriever RAG Terpadu
def retrieve_rag_context(query: str, top_k: int = RAG_TOP_K) -> tuple[str, list[dict]]:
    """Melakukan pencarian semantik ke OpenSearch dan menyusun konteks dokumen RAG."""
    try:
        # 1. Konversi teks pertanyaan menjadi vektor 768 dimensi
        query_embedding = embed_text(query, base_url=OLLAMA_BASE_URL)
        
        # 2. k-NN search ke index cinta-mama-docs
        hits = vector_store.search(OPENSEARCH_INDEX, query_embedding, k=top_k)
        if not hits:
            return "", []

        # 3. Format dan batasi panjang teks agar hemat memori
        context_parts = []
        for hit in hits:
            doc_id = hit.get("_id", "doc")
            score = hit.get("_score", 0.0)
            source_text = hit.get("_source", {}).get("text", "")
            snippet = source_text[:1200]
            context_parts.append(f"- [Dokumen: {doc_id} | Skor: {score:.4f}]\n{snippet}")

        return "\n\n".join(context_parts), hits
    except Exception:
        # Fallback aman jika terjadi kegagalan jaringan
        return "", []

7.0 Kesimpulan dan Roadmap Pembelajaran Lanjutan

Implementasi RAG pada sistem CintaMamaAI telah membuktikan bahwa integrasi model bahasa skala ringkas (3 Miliar parameter) dengan basis data vektor OpenSearch mampu menghasilkan akurasi jawaban teknis sekelas model komersial berukuran besar tanpa biaya pelatihan ulang.

Roadmap Pengembangan Selanjutnya (Modul Mendatang):

  • Document Chunking: Memecah dokumen panjang berdasarkan sub-bab (Heading H2/H3) agar representasi vektor lebih spesifik dan tidak "encer".
  • Cross-Encoder Re-Ranking: Menerapkan model peringkat kedua (reranker) untuk menyaring 10 hasil awal k-NN menjadi 3 dokumen dengan relevansi semantik tertinggi.
  • Hybrid Search: Menggabungkan algoritma pencarian kata kunci tradisional BM25 dengan k-NN vektor untuk mendapatkan hasil yang seimbang antara istilah teknis eksak dan makna konseptual.
